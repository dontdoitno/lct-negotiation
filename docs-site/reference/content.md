# Формат контента

Сценарии и персонажи лежат в JSON и правятся без участия разработчика. Типы описаны в `lib/engine/types.ts`, чтение в `lib/content/loader.ts`. Кеша в памяти нет, правка видна после перезагрузки страницы.

## Сценарий

`content/scenarios/<id>.json`

| Поле | Тип | Обязательное | Назначение |
| --- | --- | --- | --- |
| `id` | строка | да | Совпадает с именем файла |
| `title` | строка | да | Заголовок на доске разговоров и в разборе |
| `initiator` | `employee` или `manager` | да | Кто говорит первым. При `employee` сотрудник открывает разговор своей `openingLine` |
| `playerRole` | строка | да | Роль игрока коротко |
| `context` | строка | да | Ситуация на брифинге |
| `playerGoals` | массив целей | да | Цели на панели во время звонка |
| `turnLimit` | число | да | Сколько ходов до исчерпания времени. Сейчас 14 |
| `personas` | массив строк | да | Идентификаторы персонажей этого сценария |
| `config` | объект | да по типу | `domain`, `difficulty`, `tone`. Кодом не читается, см. [Конфигурируемость](../architecture/configuration.md) |
| `managerResources` | массив строк | нет | Что руководитель может предложить. Уходит в промпт с указанием не отвергать это как невозможное |
| `managerConstraints` | массив строк | нет | Чего руководитель не может. Уходит в промпт с указанием этого не требовать |
| `playerRoleDescription` | строка | нет | Роль и полномочия на брифинге, текстом на пару предложений |
| `successCriterion` | строка | нет | Формулировка победы на брифинге |

### Цель

```json
{
  "id": "g2",
  "text": "Не потерять сотрудника",
  "metric": "R",
  "threshold": 34,
  "direction": "below"
}
```

`metric` это один из кодов `R`, `T`, `I`, `S`, `C`, `A`. По умолчанию цель считается выполненной при значении не ниже `threshold`. С `direction: "below"` наоборот, при значении не выше порога. Прогресс цели показывается на панели во время звонка, а доля выполненных целей идёт в показатель «цель достигнута».

## Персонаж

`content/personas/<id>.json`. Идентификатор персонажа он же идентификатор уровня: адрес брифинга это `/brief/<id персонажа>`.

| Поле | Тип | Обязательное | Назначение |
| --- | --- | --- | --- |
| `id` | строка | да | Совпадает с именем файла |
| `scenarioId` | строка | да | К какому сценарию относится |
| `type` | `rational`, `anxious`, `aggressive` | да | Тип личности. Определяет подсказки подбора и проверку в разборе |
| `typeLabel` | строка | да | Полное название типа, например «Агрессивный (соперничающий)». Показывается только в разборе, после ответа игрока |
| `displayName` | строка | да | Имя собеседника |
| `position` | строка | да | Должность |
| `temperament` | строка | да | Темперамент и манера речи. Первая строка системного промпта |
| `backstory` | строка | да | Предыстория, которую сотрудник знает о себе |
| `goal` | строка | да | Его собственная цель в разговоре |
| `hiddenInterests` | массив слоёв | да | Скрытые причины по слоям |
| `initialState` | объект | да | Стартовые значения шести метрик |
| `reactions` | объект | да | Матрица реакций: код действия в дельты метрик |
| `adaptiveActions` | массив кодов | да | Действия, попадающие в характер: +10 к адаптивности |
| `maladaptiveActions` | массив кодов | да | Действия, не попадающие: −10 к адаптивности |
| `openingLine` | строка | да | Первая реплика, если инициатор сотрудник |
| `behaviorRules` | массив строк | да | Правила поведения в промпте, например «намекай вместо прямой просьбы» |
| `linesByResistance` | объект | да | Заготовленные реплики: `high`, `medium`, `low`, по шесть в каждой |
| `exitLine` | строка | да | Как сотрудник выходит из разговора при срыве |
| `tenure` | строка | нет | Сколько работает, для брифинга |
| `behaviorNote` | строка | нет | Что руководитель уже замечал, для брифинга |
| `trigger` | строка | нет | Почему разговор происходит сейчас, для брифинга |
| `voice` | строка | нет по факту | Голос под синтез речи. Кодом не читается |
| `triggers`, `soothers` | массивы строк | нет | Что задевает и что успокаивает. Заполнены, но кодом не читаются |
| `hiddenFailure` | булево | нет по факту | Пометка уровня. Кодом не читается, скрытый провал считается от состояния |

Поля брифинга существуют отдельно от `backstory` и `temperament` по одной причине: игроку перед звонком нельзя показывать всё, что знает о себе персонаж. Скрытые интересы на брифинг не попадают никогда.

### Слой скрытых интересов

```json
{
  "layer": 1,
  "text": "Чем лучше я работаю, тем больше на меня вешают задач.",
  "trustThreshold": 40
}
```

Слои раскрываются строго по порядку и только при двух условиях: доверие достигло `trustThreshold` и подряд сделано минимум два конструктивных действия. При раскрытии метрика интересов растёт на 100, делённое на число слоёв, а серия конструктивных действий сбрасывается.

Если `trustThreshold` не указан, берётся значение по порядковому номеру из ряда 40, 55, 70, 85.

### Матрица реакций

```json
"reactions": {
  "ack_emotion": { "R": -18, "T": 8 },
  "firm_respect": { "R": -15, "T": 10 },
  "objective_criteria": { "R": -10, "I": 10, "S": 10 },
  "pressure": { "R": 12, "T": -10 }
}
```

Ключ это код действия из списка в разделе [Метрики и действия](../reference/metrics.md), значение это дельты метрик. У каждого из шести персонажей заполнено по 19 действий. Действие, которого в матрице нет, метрики не меняет, но может дать адаптивность, если стоит в соответствующем списке.

Это основной регулятор сложности. Увеличение дельт делает разговор отзывчивее, уменьшение требовательнее.

### Стартовое состояние

```json
"initialState": { "R": 85, "T": 15, "I": 0, "S": 0, "C": 0, "A": 50 }
```

Так стартует агрессивный сотрудник в первом сценарии: разговор начинается почти со стены. Унифицированного старта для всех типов нет намеренно, это требование психологической методологии.

## Как добавить уровень

1. Создать `content/personas/<id>.json` со всеми обязательными полями.
2. Дописать `<id>` в массив `personas` нужного сценария.
3. Проверить, что тип личности задан одним из трёх допустимых значений: порядок уровней на доске строится по нему, `rational`, затем `anxious`, затем `aggressive`.
4. Заполнить `reactions` хотя бы для всех конструктивных и разрушительных действий. Нейтральные можно пропустить.
5. Проверить `linesByResistance`: шесть реплик на корзину. Они работают и как ориентир по тону в промпте, и как реплики собеседника в офлайн-режиме.
6. Запустить `npm test`. Тесты асимметрий привязаны к существующим персонажам, поэтому правка контента у них не должна ломать проверки.
7. Открыть уровень и пройти разговор в офлайн-режиме, где реплики берутся прямо из JSON. Так быстрее всего видно, что в тексте персонажа не хватает.

Новый сценарий добавляется так же: файл в `content/scenarios/`, затем персонажи со ссылкой на его `id`. Ничего регистрировать в коде не нужно, загрузчик читает папки целиком.
