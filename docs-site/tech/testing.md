# Тесты

```bash
npm test          # 53 проверки, сети не требуют
npm test -- judge # только экспериментальный режим оценки
npm run lint
```

Тесты идут на Vitest, моков базы и моков сети в них нет: всё, что проверяется, это чистые функции.

## Что покрыто

### Движок состояния, `tests/engine.test.ts`, 19 проверок

| Группа | Что проверяется |
| --- | --- |
| Детерминизм | Одинаковый вход дважды даёт одинаковый выход. Одна и та же последовательность действий не может дать разное сопротивление |
| Асимметрии между типами личности | Конкретное признание сильнее действует на тревожного, чем на агрессивного. Мягкость без конкретики нейтральна для тревожного, стоит адаптивности агрессивному, повышает сопротивление рациональному. Опора на объективные критерии сильнее всего помогает рациональному |
| Необратимость прогресса | Интересы и решения не падают даже после разрушительного хода |
| Повторная отсрочка | Вторая отсрочка считается повтором, даже если анализатор пометил ход иначе. Фиксация договорённости сбрасывает счётчик |
| Раскрытие слоёв | Слой не раскрывается без двух конструктивных действий подряд и без достаточного доверия. Раскрывается, когда выполнены оба условия |
| Условия финала | Все четыре исхода, включая отсутствие финала в середине разговора |
| Обрыв разговора | Угроза увольнением заканчивает разговор на высоком сопротивлении и не заканчивает на низком |
| Новые действия из методички | Повышение голоса бьёт по тревожному сильнее, чем по рациональному |
| Шестой уровень | Рациональный из сценария «падение результатов»: стартовая открытость, раскрытие первого слоя, потеря договорённостей на «я подумаю» без срока |

Асимметрии вынесены в тесты намеренно. Это обещание продукта, а не деталь реализации: если правка контента их сломает, тест упадёт и скажет, что именно перестало работать.

### Сценарии как данные, `tests/scenarios.test.ts`, 18 проверок

| Группа | Что проверяется |
| --- | --- |
| Сборка промта | Детерминизм, отсутствие незаполненных слотов, подстановка полей сценария, порядок слоёв, полная замена ручным промтом |
| Перевод в типы движка | Уровни метрик в числа, чувствительность как множитель дельт, цена раскрытия слоя, метрики и пороги целей |
| Устойчивость черновика | Валидация не падает на записи, сохранённой до появления нового поля, и сообщает о нём как о незаполненном |

### Экспериментальный режим оценки, `tests/judge.test.ts`, 21 проверка

| Группа | Что проверяется |
| --- | --- |
| Предфильтр | Пустая и слишком короткая реплика, оффтоп, оскорбление с правильными дельтами, попытка внедрить инструкцию в промпт |
| Ограничение дельт | Умножение на шаг, потолок изменения метрики за ход, границы 0 и 100, включая случай, когда шаг больше потолка |
| Разбор ответа судьи | Валидный JSON, битый JSON с переходом в деградацию, обрыв транспорта с переходом в деградацию |
| Завершение уровня | Пороги успеха и провала |

Проверки идут на `MockClient`, поэтому сеть не нужна. Маркеры `__FORCE_INVALID_JSON__` и `__FORCE_ERROR__` в тексте реплики позволяют проверить повтор и деградацию без настоящих сбоев.

## Чего тесты не покрывают

Честный список, чтобы не создавать ложного впечатления о покрытии.

- Интерфейсных тестов нет. Ни одного компонента React в тестах не участвует.
- Обработчики API не покрыты. Оркестрация хода проверяется прогоном по HTTP вручную, пример в разделе [Проверка после перезапуска](../run/restart.md).
- Эвристика анализатора не покрыта отдельными тестами. Её поведение видно косвенно: правила определяют, какие действия попадут в движок.
- Настоящие обращения к моделям не тестируются, и это осознанно: тест, зависящий от внешней платной платформы, недостоверен.

## Линтер

`npm run lint` сейчас даёт три ошибки правила `react-hooks/set-state-in-effect`: `app/call/[sessionId]/page.tsx:66`, `components/call/LiveMetrics.tsx:20`, `lib/call/useSpeechInput.ts:38`. Во всех трёх случаях состояние меняется синхронно внутри эффекта, что приводит к лишнему проходу рендера.

На работу это не влияет, экран звонка работает. Ошибки перечислены здесь, а не замолчаны, чтобы вывод линтера не расходился с документацией. Сборка `npm run build` при этом проходит: линтер в неё не входит.
