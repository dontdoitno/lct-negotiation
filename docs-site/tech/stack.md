# Стек и библиотеки

## Основное

| Технология | Версия | Роль |
| --- | --- | --- |
| Next.js | 16.3.6 | Фронтенд и бэкенд в одном процессе: App Router для страниц, Route Handlers для API, Turbopack для сборки |
| React | 19.2.8 | Интерфейс. Серверные компоненты для страниц, клиентские для интерактивных экранов |
| TypeScript | 5 | Весь код, включая контент-типы и движок |
| Tailwind CSS | 4 | Разметка и отступы через утилитарные классы |
| Prisma | 6.19.3 | ORM и миграции |
| PostgreSQL | управляемый | База данных. Локально и в облаке одна и та же, подключение из `DATABASE_URL` |
| Zod | 4.6.5 | Проверка ответов языковой модели: схема анализатора и схема судьи |
| Vitest | 4.1.11 | Юнит-тесты |
| ESLint | 9 | Линтер, конфигурация `eslint-config-next` |

Отдельного бэкенд-сервиса нет, отдельной базы на сервере нет, брокера сообщений нет. Решение принято ради скорости запуска на чужой машине: клонировать, поставить зависимости, применить миграции, запустить.

## Дизайн-система

| Пакет | Версия | Роль |
| --- | --- | --- |
| `@astryxdesign/core` | 0.6.3 | Компоненты и типографика |
| `@astryxdesign/cli` | 0.6.3 | Сборка темы из `theme.ts` |
| `@astryxdesign/theme-neutral` | 0.6.3 | Базовая тема, поверх которой задан акцент |
| `@stylexjs/stylex` | 0.19.1 | Стили внутри компонентов дизайн-системы |

Используются компоненты `Text`, `Heading`, `Button`, `Card`, `SelectableCard`, `Badge`, `Avatar`, `Link`, `ProgressBar`, `TextInput`, `VisuallyHidden`.

Весь текст на экранах идёт через `Text` и `Heading`, а не через голые теги, чтобы типографика и цвета оставались едиными. Тема задана в `theme.ts`: акцент `#3454D1`, заголовки Wix Madefor Display, основной текст Manrope, моноширинный JetBrains Mono. Кириллица есть у всех трёх шрифтов, это проверялось отдельно, потому что интерфейс полностью русский, а многие подходящие по рисунку шрифты кириллицы не имеют.

Три ширины контейнера на всё приложение: 440, 640 и 1400 пикселей. Узкая под формы, средняя под текст, широкая под доску разговоров и разбор.

## Что где лежит

```
app/
  api/                 Route Handlers: сессии, ходы, разбор, ветвление, режим судьи
  brief/ call/ cases/  Экраны пользовательского пути
  quiz/ rules/ learn/
  session/[id]/        Экран финала и разбор
lib/
  engine/              Движок состояния, условия финала, оценка. Чистый TypeScript
  llm/                 Анализатор, актёр, провайдеры моделей
  flow/                Маршруты, копирайт интерфейса, подбор уровня, сборка разбора
  call/                Состояние экрана звонка, SSE, распознавание речи
  content/             Чтение сценариев и персонажей с диска
  judge/               Экспериментальный режим оценки
components/            Компоненты экранов
content/               Сценарии и персонажи в JSON
prompts/               Промпты режима судьи в отдельных файлах
prisma/                Схема и миграции
tests/                 Юнит-тесты
docs/                  Исходные спецификации, не публикуются
docs-site/             Эта документация
```

Разделение между `lib/engine` и `lib/llm` намеренное и проверяется при чтении кода: в `lib/engine` нет ни одного импорта из `lib/llm`, поэтому движок нельзя случайно сделать зависимым от модели.

## Приёмы, которые стоит назвать

**Server-Sent Events для хода.** Ход отвечает потоком, а не одним JSON, поэтому метрики появляются на панели раньше, чем собеседник договорил. Реализация в `lib/call/sse.ts` на стороне клиента и в обработчике `app/api/session/[id]/turn/route.ts` на стороне сервера.

**Чистое ядро.** `applyTurn`, `checkEnding`, `computeOutcome`, `applyDeltas` это функции без побочных эффектов. Отсюда тесты без моков и без базы.

**Закрытый список действий.** Свободный текст превращается в коды из перечисления на 20 значений, и только они доходят до движка. Модель не может расширить словарь на ходу.

**Проверка ответов модели схемой.** Ответ анализатора и ответ судьи разбираются через Zod. Невалидный ответ означает возврат к детерминированной замене, а не падение хода.

**Контент как данные.** Психологическая модель живёт в JSON, а не в коде. Правки не требуют ни сборки, ни деплоя.

**Распознавание речи браузером.** Web Speech API с языком `ru-RU`, `lib/call/useSpeechInput.ts`. Внешний сервис не нужен, ключи не нужны. Если браузер не поддерживает, интерфейс остаётся в текстовом режиме.

## Объявлено, но не используется

`zustand` и `uuid` есть в зависимостях, но ни одного импорта в коде нет. Состояние экрана звонка собрано на обычном редьюсере в `lib/call/reducer.ts`, идентификаторы генерируют Prisma и `crypto.randomUUID`. Пакеты можно удалить.
