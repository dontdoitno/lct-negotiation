# Проверка после перезапуска

Прототип не должен терять работоспособность и данные от перезапуска процесса или машины. Здесь то, что выживает, что нет, и как это проверить за пару минут.

## Что выживает

**Все сессии, ходы и разборы.** Они лежат в файле `prisma/dev.db`. Процесс не держит состояние разговора в памяти: после каждого хода состояние записывается и в `Session.state`, и в `Turn.stateAfter`. Незавершённый разговор после перезапуска продолжается с последнего записанного хода.

**Ваша личность в системе.** Cookie `uid` живёт год, и все сессии привязаны к ней. Открыв браузер заново, вы видите свои прошлые разговоры на доске.

**Ответы входного опроса, отметка о пройденном обучении, ответ про тип личности.** Они в localStorage браузера, перезапуск сервера их не касается.

**Контент.** Сценарии и персонажи читаются с диска на каждый запрос, кеша в памяти нет. Правка JSON видна после перезагрузки страницы, даже без перезапуска сервера.

## Что не выживает

**Ход, прерванный на середине генерации.** Запись в базу происходит после того, как собеседник договорил. Если процесс убить во время генерации, этот ход не сохранится, и разговор останется на предыдущем. Полузаписанного состояния при этом не возникает.

**Выбранный провайдер модели.** Он определяется один раз на процесс и кешируется. Правка `.env` требует перезапуска сервера, сама она не подхватится.

## Чего не делать перед показом

- `npx prisma migrate reset` удаляет базу вместе со всеми разговорами.
- Удаление `prisma/dev.db` делает то же самое. Файл в `.gitignore`, поэтому из репозитория он не восстановится.
- Переключение `MOCK_MODE` в `false` без рабочих ключей оставит продукт без реплик собеседника. Проверять связку с моделью нужно заранее, а не за пять минут до демонстрации.

## Проверка за две минуты

```bash
# 1. Рабочая сборка
npm run build
npm start

# 2. В другом терминале: страницы отвечают
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/cases

# 3. Разговор целиком по API, без браузера
SID=$(curl -s -X POST http://localhost:3000/api/session \
  -H "Content-Type: application/json" \
  -d '{"levelId":"s1-rational"}' | python3 -c "import json,sys; print(json.load(sys.stdin)['sessionId'])")
echo "сессия: $SID"

curl -s -X POST "http://localhost:3000/api/session/$SID/turn" \
  -H "Content-Type: application/json" \
  -d '{"text":"Вижу, что тебе тяжело. Расскажи, что именно не получается?"}'

# 4. Перезапустить сервер: Ctrl+C, затем снова npm start

# 5. Сессия на месте вместе с ходом
curl -s "http://localhost:3000/api/session/$SID" | head -c 400
```

На третьем шаге ответ приходит потоком SSE. В нём должны быть по порядку: `event: analysis` с распознанными действиями, `event: state` с метриками, затем `event: npc_chunk` с текстом и `event: npc_done` со статусом.

На пятом шаге сессия должна вернуться с тем же состоянием, что и до перезапуска. Если да, критерий выполнен.

## Проверка на чистой машине

Чтобы убедиться, что дело не в вашем локальном окружении:

```bash
git clone https://github.com/dontdoitno/lct-negotiation.git
cd lct-negotiation
npm install
cp .env.example .env
npx prisma migrate deploy
npx prisma generate
npm run build
npm start
```

`migrate deploy` вместо `migrate dev` применяет готовые миграции и ничего не спрашивает, что удобно в скриптах и в CI. Ключи на этом пути не нужны: в `.env.example` включён офлайн-режим.

## Известное ограничение окружения на macOS

На Apple Silicon бывает, что нативные бинарники в `node_modules` собраны под другую архитектуру, чем запущенный Node.js. Это ломает сборку CSS с ошибкой вида `Cannot find module '../lightningcss.darwin-*.node'`. Причина и лечение в разделе [Если что-то не работает](troubleshooting.md).
