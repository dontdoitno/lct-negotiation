# Быстрый старт

## Что нужно на машине

- Node.js версии 20.9 или новее. Проверено на 24.12. Требование идёт от Next.js 16.
- npm, он ставится вместе с Node.js.
- Около 700 МБ свободного места под `node_modules`.

- Строка подключения к PostgreSQL. Где её взять, разобрано ниже.

GPU и другое нестандартное железо не нужны. Ключи к языковым моделям для первого запуска тоже не нужны: `.env.example` включает офлайн-режим, и разговор проходит на заготовленных репликах.

## Где взять базу

Нужна пустая база PostgreSQL. Подойдёт любая из трёх:

**Та же база, что у развёрнутого приложения.** Если проект уже связан с Vercel, строки подключения выдаются одной командой:

```bash
vercel env pull .env.local --yes
```

**Своя облачная база.** Любой провайдер PostgreSQL. В `.env` нужны две строки: `DATABASE_URL` для рантайма и `DATABASE_URL_UNPOOLED` для миграций. Если пула соединений нет, впишите в обе одно и то же значение.

**Локальный PostgreSQL.** Например через Docker:

```bash
docker run --name razbor-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:17
```

Тогда обе переменные равны `postgresql://postgres:postgres@localhost:5432/postgres`.

## Пять команд

```bash
npm install
cp .env.example .env          # вписать DATABASE_URL и DATABASE_URL_UNPOOLED
npx prisma migrate deploy
npx prisma generate
npm run dev
```

Открыть `http://localhost:3000`.

Что делает каждая команда:

1. `npm install` ставит зависимости.
2. `cp .env.example .env` создаёт конфигурацию. В ней уже стоит `MOCK_MODE="true"`, то есть офлайн-режим без обращений к сети. Строки подключения к базе вписываются сюда.
3. `npx prisma migrate deploy` применяет миграцию из `prisma/migrations/` к пустой базе. Вопросов не задаёт.
4. `npx prisma generate` собирает клиент Prisma под вашу платформу.
5. `npm run dev` поднимает сервер разработки на порту 3000.

## Что проверить сразу после запуска

Пройдите путь целиком, он занимает пару минут:

1. `http://localhost:3000` открывает лендинг.
2. Кнопка «Попробовать разговор» ведёт в опрос из трёх вопросов.
3. «Продолжить как гость» на экране регистрации пропускает регистрацию, которой в прототипе и нет.
4. На доске разговоров открыт один разговор, подобранный по вашим ответам. Откройте его.
5. С брифинга начинается звонок. Напишите любую реплику и отправьте.
6. Панель справа должна обновиться, а собеседник ответить.
7. Дойдите до конца разговора или сделайте 14 ходов и посмотрите разбор.

Если на шестом шаге метрики не двинулись, ищите ответ в разделе [Если что-то не работает](troubleshooting.md).

## Запуск в рабочем режиме

Так продукт запускается не для разработки, а для показа:

```bash
npm run build
npm start
```

Тот же адрес, `http://localhost:3000`. Сборка занимает заметно больше времени, чем `npm run dev`, зато страницы открываются быстрее и не перекомпилируются на каждый запрос. На демонстрации лучше использовать именно этот режим.

Команда `npm run build` заодно генерирует клиент Prisma и накатывает миграции: так требует сборка на Vercel, где `node_modules` берётся из кеша. Если база уже готова и хочется собрать только приложение, есть `npm run build:local`.

## Другой порт

Порт 3000 бывает занят:

```bash
npm run dev -- --port 3010
npm start -- --port 3010
```

## Работа с ключами языковой модели

Офлайн-режим полностью играбелен: движок, метрики, слои интересов и разбор работают одинаково, отличается только источник реплик собеседника. В офлайн-режиме он говорит заготовленными фразами из своего JSON, по шесть на каждый уровень сопротивления.

Чтобы реплики генерировала модель, нужно прописать ключи в `.env` и убрать `MOCK_MODE="true"`. Пошагово это описано в разделе [Внешние сервисы и ключи](../tech/services.md).
