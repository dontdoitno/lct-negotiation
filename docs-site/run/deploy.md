# Деплой на Vercel

Приложение это один процесс Next.js, поэтому на Vercel оно разворачивается без переупаковки. Настроить нужно ровно две вещи: базу данных и переменные окружения. Всё остальное в репозитории уже подготовлено.

## Что уже сделано в репозитории

| Что | Где | Зачем |
| --- | --- | --- |
| PostgreSQL вместо файловой базы | `prisma/schema.prisma` | Файловая система функций на Vercel эфемерная и доступна только на чтение. Файл SQLite не пережил бы холодный старт, и у разных экземпляров функции были бы разные базы |
| `directUrl` для миграций | `prisma/schema.prisma` | Через пул соединений Prisma не может взять advisory lock, и миграции не применяются |
| `binaryTargets` с `rhel-openssl-3.0.x` | `prisma/schema.prisma` | Движок запроса Prisma под рантайм функций. Без него клиент собирается локально, но падает в облаке |
| Миграция под PostgreSQL | `prisma/migrations/0_init/` | Прежние миграции были написаны под SQLite и содержали тип `DATETIME`, которого в PostgreSQL нет |
| `outputFileTracingIncludes` | `next.config.ts` | Сценарии, персонажи и промпты читаются с диска по пути из `process.cwd()`. Статический анализ такой путь не видит, и без этой настройки папки `content/` и `prompts/` не попадают в бандл функции, а каждый уровень отвечает 500 |
| `prisma generate` и `prisma migrate deploy` в сборке | `package.json` | Vercel берёт `node_modules` из кеша, поэтому `postinstall` может не выполниться, а клиент Prisma обязан быть собран под платформу |
| Регион Франкфурт и лимит времени на ход | `vercel.json` | По умолчанию функции живут в Вирджинии, и каждый ход ходил бы через Атлантику в Yandex Cloud и обратно |

Проверено локально: контент попадает в трассировку функций, `prisma migrate diff` даёт корректный DDL для PostgreSQL, сборка проходит.

## Что нужно сделать вам

Эти шаги требуют вашего аккаунта, выполнить их за вас нельзя.

### 1. Вход и связка проекта

```bash
npm i -g vercel@latest
vercel login
vercel link
```

### 2. База данных

Подключается из Vercel Marketplace: провайдер сам создаёт базу и прокидывает переменные в проект.

```bash
vercel integration add neon
```

Если команда уводит в браузер, дооформите подключение там: часть интеграций не умеет проходить авторизацию из терминала.

После подключения в проекте появятся `DATABASE_URL` и `DATABASE_URL_UNPOOLED`. Забрать их себе:

```bash
vercel env pull .env.local --yes
```

### 3. Создать таблицы

```bash
set -a; source .env.local; set +a
npx prisma migrate deploy
```

Prisma сам читает только `.env`, а `vercel env pull` пишет в `.env.local`, поэтому переменные подгружаются в окружение вручную. Вариант через пакет: `npx dotenv-cli -e .env.local -- npx prisma migrate deploy`. Просто `npx dotenv` не сработает: так называется библиотека без исполняемого файла, а нужен `dotenv-cli`.

Чтобы дальше все команды Prisma работали без приставок, допишите обе строки подключения в `.env`.

Накат миграций произойдёт и сам при каждой сборке, но первый раз удобнее сделать руками, чтобы увидеть ошибки сразу.

### 4. Переменные языковой модели

В Settings → Environment Variables добавить то, что не приходит от базы:

| Переменная | Значение |
| --- | --- |
| `MOCK_MODE` | `false` для настоящих реплик, `true` для офлайн-демонстрации |
| `LLM_PROVIDER` | `yandex` |
| `YANDEX_API_KEY` | ключ сервисного аккаунта |
| `YANDEX_FOLDER_ID` | идентификатор каталога |
| `YANDEX_API_MODE` | `native` |
| `YANDEX_MODEL` | `yandexgpt-lite` |
| `ANALYZER_LLM` | `false` |

Расшифровка каждой на странице [Переменные окружения](environment.md).

!!! warning "Офлайн-режим как страховка"
    С `MOCK_MODE=true` развёрнутое приложение работает целиком: метрики, слои интересов, исход и разбор считаются тем же движком, отличаются только реплики собеседника. Если до показа не успеваете настроить ключи или заканчивается грант, деплой всё равно останется играбельным.

### 5. Деплой

```bash
vercel --prod
```

Либо просто пуш в `main`, если проект связан с репозиторием на GitHub.

## Что проверить после первого деплоя

1. Открывается главная.
2. `/cases` показывает шесть карточек.
3. Брифинг любого уровня открывается: значит `content/` доехал до функции.
4. Один ход в разговоре проходит и панель метрик обновляется: значит база пишется, а провайдер модели отвечает.
5. Перезагрузить страницу разбора: сессия должна остаться на месте.

Если третий пункт даёт 500, а локально всё работает, смотрите в логи функции: почти наверняка это трассировка файлов, то есть `outputFileTracingIncludes`.

## Чего менять не нужно

Потоковая передача хода по SSE работает на обычном рантайме Node, объявлять Edge не нужно и не следует: на Edge не будет ни Prisma, ни чтения файлов. Прослойка `proxy.ts` из Next 16 поддерживается, анонимная cookie продолжает работать. Голосовой ввод требует защищённого соединения, и на домене Vercel оно есть по умолчанию.
