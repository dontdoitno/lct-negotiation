# Генерация черновика

Адрес `/admin/scenarios/generate`. Форма ровно из тех полей, которые ТЗ называет контекстом на входе.

| Поле | Пример |
| --- | --- |
| Сфера | Продажи |
| Тема переговоров | Клиент требует скидку, которой нет в прайсе |
| Сложность | Сложная |
| Тон собеседника | Агрессивный |
| Роль собеседника | Потенциальный покупатель |
| Цель собеседника | Добиться цены ниже прайса |

Кнопка «Сгенерировать черновик» отправляет их модели. Она заполняет название, имя собеседника, контекст, слои скрытых интересов, цели игрока, критерии успеха, ресурсы, ограничения и первую реплику.

## Что модель не решает

Поведение персонажа приходит из пресета тона, а не от модели. Матрица реакций, стартовые метрики, шкала сопротивления и правила поведения подставляются готовыми.

Это не экономия, а условие воспроизводимости. Если бы матрицу писала модель, исход разговора перестал бы быть предсказуемым, а именно на предсказуемости держится весь продукт.

## Результат

Черновик сразу сохраняется и открывается в конструкторе. Все поля редактируемы, статус «Черновик», в пользовательском каталоге его нет.

Сохранение до открытия формы нужно затем, чтобы результат генерации не потерялся при перезагрузке страницы.

## Если модель недоступна

Форма всё равно работает. Черновик собирается из ближайшего пресета и введённых значений, с подсказками в полях вместо текста, который должна была написать модель.

Это осознанное требование: демонстрация не должна падать из-за внешнего API. То же правило действует в офлайн-режиме, когда ключей нет вовсе.

## Состояния

Во время генерации кнопка показывает, что это займёт несколько секунд. При ошибке появляется сообщение с предложением повторить или заполнить руками. Рядом всегда есть выход на пустой конструктор и отмена.
