# Симулятор управленческих переговоров — полная спецификация

**Версия:** 1.0 · **Дата:** 24.09.2026
**Команда:** фуллстек-разработчик + психолог · **Срок:** 2 недели
**Формат:** веб-платформа, интерфейс видеозвонка с ИИ-сотрудником

---

## 1. Что делаем

Руководитель заходит на сайт, выбирает сценарий и попадает в окно, похожее на Zoom. На связи ИИ-сотрудник. Руководитель разговаривает с ним голосом или текстом. Справа — панель с текущим состоянием собеседника и целями разговора. После разговора — разбор и возможность переиграть.

**Целевая аудитория:** руководители линейного и среднего звена — от тимлида до начальника отдела.

**Главное архитектурное решение:** состояние персонажа считает детерминированный движок на бэкенде, а не сама языковая модель. Модель только отыгрывает реплику в уже посчитанном состоянии. Отсюда три следствия:

1. Исход воспроизводим — один и тот же набор действий даёт один и тот же результат.
2. Персонажа нельзя продавить просто потому, что модель склонна соглашаться.
3. Метрики на экране честные, а не «нейросеть так решила».

Это и есть то, чем решение отличается от «промпта в ChatGPT».

### Объём MVP

2 сценария × 3 типа личности = **6 уровней**.

| № | Сценарий | Тип | Роль в продукте |
|---|---|---|---|
| 1 | Перегрузка сотрудника | Рациональный | онбординг, самый предсказуемый |
| 2 | Перегрузка сотрудника | Тревожный | вводит механику скрытого провала |
| 3 | Перегрузка сотрудника | Агрессивный | демо для жюри |
| 4 | Сложная задача с риском срыва | Рациональный | |
| 5 | Сложная задача с риском срыва | Тревожный | |
| 6 | Сложная задача с риском срыва | Агрессивный | |

Плюс админ-контур настройки контекста (требование ТЗ, гл. 2 п. 2 и критерий 8.2).

## 2. Модель метрик — ядро продукта

Шесть метрик из методологии психолога. Внутри системы каждая — число **0–100**. Наружу отдаётся бакет, потому что игроку нужна не точность, а направление.

| Код | Название | Что измеряет | Бакеты |
|---|---|---|---|
| **R** | Сопротивление | насколько не принимает аргументы | высокое (67–100) / среднее (34–66) / низкое (0–33) |
| **T** | Открытость | насколько говорит правду | низкая / средняя / высокая |
| **I** | Ясность интересов | понял ли руководитель скрытые мотивы | нет / частично / полностью |
| **S** | Пространство решений | сколько вариантов найдено | нет / один / несколько |
| **C** | Согласованность | есть ли чёткие договорённости | нет / частично / есть |
| **A** | Адаптивность | попадает ли игрок в характер | нет / частично / попал |

**Две группы, ведут себя по-разному:**

- **R, T, A** — состояние персонажа. Меняются в обе стороны каждый ход.
- **I, S, C** — прогресс разговора. Растут монотонно: раз вскрытый интерес нельзя «забыть». Не набрать можно, потерять — нет. Исключение: `C` падает при повторном «я подумаю» у тревожного (формальное согласие обнуляется).

### Стартовые состояния

| Тип | R | T | I | S | C | A |
|---|---|---|---|---|---|---|
| Рациональный (компромиссный) | 45 | 50 | 0 | 0 | 0 | 50 |
| Тревожный (избегающий) | 50 | 40 | 0 | 0 | 0 | 50 |
| Агрессивный (соперничающий) | 85 | 15 | 0 | 0 | 0 | 50 |

### Таксономия действий игрока

Закрытый список. Анализатор классифицирует каждую реплику только по нему — иначе движок ломается. Одна реплика = 1–3 действия.

**Конструктивные:**

| Код | Значение |
|---|---|
| `ack_emotion` | признание эмоции («вижу, ты на взводе») |
| `firm_respect` | твёрдость с уважением |
| `open_question` | открытый вопрос |
| `specific_recognition` | конкретное признание работы (не общая похвала) |
| `offer_options` | предложение вариантов |
| `objective_criteria` | опора на объективные критерии (нагрузка команды, данные, правила) |
| `commit_fix` | фиксация договорённости с конкретикой |
| `apology` | признание своей ошибки |
| `postpone_with_deadline` | «я подумаю» со сроком |

**Деструктивные:**

| Код | Значение |
|---|---|
| `blame` | обвинение |
| `pressure` | давление |
| `ignore_emotion` | игнорирование эмоции |
| `mirror_aggression` | зеркалирование агрессии |
| `direct_criticism` | прямая критика без опоры |
| `softness_no_substance` | мягкость без конкретики |
| `postpone_no_deadline` | «я подумаю» без срока |
| `postpone_repeat` | повторное «я подумаю» |

**Нейтральные:** `small_talk`, `clarify_fact`, `off_topic`.

**Обратите внимание на три ключевые асимметрии** — их стоит показать жюри:

- `specific_recognition`: тревожный −25 к сопротивлению, агрессивный −8. Похвала работает на того, кто боится оказаться плохим.
- `softness_no_substance`: тревожному всё равно (0), агрессивный теряет уважение (A −15), рациональный раздражается (R +8).
- `objective_criteria`: рациональному −20, агрессивному −10. Цифры убеждают того, кто мыслит цифрами.

### Адаптивность (A)

У каждого персонажа два списка в JSON:

```json
"adaptiveActions":    ["firm_respect", "objective_criteria", "commit_fix"],
"maladaptiveActions": ["softness_no_substance", "apology"]
```

Попал в список адаптивных → `A += 10`. В маладаптивные → `A -= 10`. Для тревожного списки ровно обратные: туда попадают `specific_recognition` и `ack_emotion`, а `firm_respect` без набранного доверия — в маладаптивные.

### Раскрытие скрытых интересов

У каждого персонажа 3–4 слоя. Счётчик `constructiveStreak`: +1 за конструктивное действие, сброс в 0 при деструктивном.

```
если constructiveStreak >= 2 и T >= порог_следующего_слоя:
    раскрыть слой
    I += 100 / количество_слоёв
    constructiveStreak = 0
```

Пороги `T` по слоям: 40 / 55 / 70 / 85. Это гарантирует, что глубокие вещи («я на грани выгорания», «боюсь, что сочтут слабым») не вываливаются на первом ходу.

### Условия завершения

| Исход | Условие | Что происходит |
|---|---|---|
| **Успех** | `R < 34` и `C >= 70` и `I >= 70` | персонаж сам предлагает зафиксировать: «Давайте запишем» |
| **Срыв** | `R >= 90` три хода подряд | персонаж завершает разговор |
| **Лимит** | исчерпаны 14 ходов | разговор обрывается на текущем состоянии |

Срыв выглядит по-разному:
- **Агрессивный** уходит с угрозой: «Если ничего не изменится, я буду искать другое место».
- **Тревожный** тихо соглашается и уходит: «Хорошо… Я понял». Игроку кажется, что он победил. В разборе выяснится, что нет.
- **Рациональный** формально фиксирует минимум и закрывается.

Без возможности проиграть нет ставки. Это обязательная механика, не опциональная.

## 3. Архитектура

```
┌──────────────────────────────────────────────────────┐
│  FRONTEND — Next.js 15 App Router + TypeScript       │
│  Zoom-интерфейс · панель метрик · голос · разбор     │
└───────────────────────┬──────────────────────────────┘
                        │ REST + SSE
┌───────────────────────▼──────────────────────────────┐
│  BACKEND — Next.js Route Handlers (Node runtime)     │
│                                                       │
│   ┌──────────── Turn Orchestrator ───────────────┐   │
│   │  1. STT          (если голосовой ввод)       │   │
│   │  2. Analyzer LLM → строгий JSON действий     │   │
│   │  3. State Engine → чистый TS, БЕЗ LLM        │   │
│   │  4. Actor LLM    → реплика (стриминг)        │   │
│   │  5. TTS          → аудио                     │   │
│   └───────────────────────────────────────────────┘   │
│                                                       │
│   Scenario Loader │ Debrief Builder │ Admin API      │
└───────────────────────┬──────────────────────────────┘
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   Postgres/SQLite   LLM-провайдер   SpeechKit
   (Prisma)          (2 вызова/ход)  (STT + TTS)
```

### Стек

| Слой | Выбор | Почему именно так |
|---|---|---|
| Фронт + бэк | Next.js 15 + TypeScript | один разработчик, один репозиторий, один деплой |
| Стили | Tailwind + shadcn/ui | тёмная тема из коробки, скорость вёрстки |
| БД | SQLite локально → Postgres (Neon) на проде | миграция меняет одну строку в Prisma |
| LLM | OpenRouter как основной, GigaChat/YandexGPT как резерв | адаптер изолирован, смена провайдера = одна реализация интерфейса |
| STT | Yandex SpeechKit, fallback — Web Speech API | SpeechKit точнее на русском, Web Speech бесплатен и работает без ключей |
| TTS | Yandex SpeechKit, 3 разных голоса | голос даёт половину погружения |
| Состояние на клиенте | Zustand | легче Redux, функционала хватает |
| Деплой | Vercel + Neon | ТЗ требует публичную ссылку |

**Критичное требование к коду:** весь доступ к LLM изолирован в `lib/llm/provider.ts` с интерфейсом:

```ts
interface LLMProvider {
  complete(messages: Message[], opts?: { schema?: JSONSchema; temperature?: number }): Promise<string>;
  stream(messages: Message[], opts?: { temperature?: number }): AsyncIterable<string>;
}
```

Туда же встроен `MOCK_MODE=true` — возвращает заранее записанные ответы из `/mocks`. Это офлайн-режим для демо, требование ТЗ (гл. 3, «чего избегать»). Реализуется за полчаса, спасает питч.

## 5. Логика одного хода

```
POST /api/session/{id}/turn
Content-Type: multipart/form-data
body: { text?: string, audio?: Blob, inputMode: "voice" | "text" }
Ответ: text/event-stream (SSE)
```

### Шаг 1. Распознавание речи

Если `inputMode === "voice"`: аудио → SpeechKit → текст. Таймаут 8 секунд. При ошибке возвращаем `{ error: "stt_failed" }`, ход не засчитывается, на экране — «Не расслышал, повторите или напишите текстом».

**Важно для UX:** распознанный текст показываем игроку до отправки, с возможностью поправить. Это спасает демо при плохом микрофоне.

### Шаг 2. Анализатор

Отдельный вызов LLM, температура 0, структурированный вывод, ~150 токенов на ответ.

```

ПОСЛЕДНИЕ РЕПЛИКИ:
{4 последних хода}

РЕПЛИКА РУКОВОДИТЕЛЯ: "{text}"

{

  "tone": "calm" | "firm" | "soft" | "harsh",

}

   "rationale":"Вы назвали его состояние и предложили искать решение вместе."}
```

`rationale` идёт прямо на экран как микро-фидбек. Это главный обучающий элемент: человек понимает связь между своей репликой и реакцией в моменте, а не через десять минут в отчёте.

### Шаг 3. Движок состояния

Чистый TypeScript, ни одного вызова LLM. Единственное место, где определяется исход.

```ts
export function applyTurn(
  state: SessionState,
  actions: ActionCode[],
  persona: Persona
): SessionState {
  const next: SessionState = { ...state };
  const before = { ...state };

  for (const action of actions) {
    const delta = persona.reactions[action] ?? {};
    for (const [metric, value] of Object.entries(delta)) {
      next[metric] = clamp(next[metric] + value, 0, 100);
    }
    if (persona.adaptiveActions.includes(action))    next.A = clamp(next.A + 10, 0, 100);
    if (persona.maladaptiveActions.includes(action)) next.A = clamp(next.A - 10, 0, 100);

    next.constructiveStreak = CONSTRUCTIVE.includes(action)
      ? next.constructiveStreak + 1
      : 0;
  }

  // прогресс-метрики не откатываются
  next.I = Math.max(next.I, before.I);
  next.S = Math.max(next.S, before.S);

  next.turn = before.turn + 1;
  next.highResistanceStreak = next.R >= 90 ? next.highResistanceStreak + 1 : 0;

  revealInterestIfReady(next, persona);
  return next;
}

export function checkEnding(state: SessionState, scenario: Scenario): Ending | null {
  if (state.R < 34 && state.C >= 70 && state.I >= 70) return "success";
  if (state.highResistanceStreak >= 3)                return "failed";
  if (state.turn >= scenario.turnLimit)               return "timeout";
  return null;
}
```

Этот файл покрывается юнит-тестами — не ради качества кода, а ради того, чтобы на демо ничего не сломалось.

### Шаг 4. Актёр

Вызов LLM со стримингом, температура 0.8.

```
{системный промпт персонажа: характер, бэкстори, цель, правила поведения}

ТВОЁ ТЕКУЩЕЕ СОСТОЯНИЕ:

Открытость: {низкая|средняя|высокая}

ЧТО ТОЛЬКО ЧТО СДЕЛАЛ РУКОВОДИТЕЛЬ: {действия человеческими словами}

{если сработало условие срыва:}
ЗАВЕРШИ РАЗГОВОР. {стиль завершения для типа}

{если сработало условие успеха:}
```

Состояние **подставляется** в промпт, а не вычисляется моделью. Модель не может «передумать и смягчиться» — она получает готовое число.

Реплика → SpeechKit → ogg → URL. Запускается параллельно со стримингом текста, чтобы не ждать. Если TTS не ответил за 5 секунд — показываем только текст, ход не блокируем.

## 6. Интерфейс

### 6.1. Карта уровней (главная)

Сетка 2 колонки × 3 строки — по строке на тип личности, по колонке на сценарий. Карточка уровня:

- Портрет персонажа (приглушённый, если уровень закрыт)
- Имя + должность
- Название сценария
- Тип личности с иконкой
- Звёзды (0–3), число попыток
- Замок, если закрыт

Сверху — прогресс-бар «Пройдено 2 из 6» и кнопка «Мой профиль» (появляется после второго уровня).

| Счётчик ходов | полоски, не цифра | визуально создаёт дефицит |
| Раскрытые интересы | накапливаются в панели справа | видимый прогресс, ощущение раскопок |
| Очки | всплывают справа снизу, +25 / −15 | мгновенная обратная связь |

**Голосовой ввод.** Push-to-talk: удерживать пробел или кнопку микрофона. Во время записи — живая осциллограмма по данным с микрофона. После отпускания — распознанный текст в поле ввода с курсором, можно поправить, отправка по Enter. Переключатель «текст / голос» всегда на виду.

**Никакого распознавания в реальном времени.** Это источник багов, а выигрыша по ощущениям почти нет.

### 6.5. Разбор

**Блок 1. Четыре метрики результата** (из методологии психолога):

| Метрика | Формула |
|---|---|
| Цель руководителя достигнута | доля выполненных `playerGoals`, % |
| Удовлетворённость сотрудника | `(100−R)·0.4 + T·0.3 + I·0.3` |
| Готовность выполнять договорённости | `C·0.5 + T·0.3 + S·0.2` |
| Риск конфликта, саботажа, увольнения | `R·0.5 + (100−T)·0.3 + (100−C)·0.2` |

**Скрытый провал.** Если `C >= 70`, но `T < 40` — отдельный красный блок:

> **Он согласился, но не поверил вам.**
> Формально договорённости есть. Но открытость осталась низкой: он не сказал, что происходит на самом деле, и согласился, чтобы разговор закончился. Риск увольнения — 78%.

Это самый сильный момент всего продукта. Руководитель уходит с ощущением победы, а система показывает, что он потерял человека. На тревожном типе это срабатывает почти всегда.

**Блок 2. Таймлайн.** Все ходы лентой. 2–3 отмечены как переломные — те, где `|ΔR|` максимальна. Клик по ходу раскрывает: что вы сказали → как это классифицировано → что изменилось → почему.

**Блок 3. Гипотезы против реальности.** Ответы с экрана рефлексии рядом с фактами. Полная карта скрытых интересов с отметкой, какие слои удалось вскрыть, а какие остались закрыты и что для этого было нужно.

**Блок 4. Ровно две рекомендации.** Не десять. Формулирует психолог под паттерны из раздела 7. Правило формулировки: про поведение, не про личность.

> Вы трижды переводили разговор на сроки проекта сразу после того, как он говорил о своём состоянии. Каждый раз сопротивление росло. Попробуйте сначала назвать то, что слышите, и только потом переходить к делу.

**Блок 5. Кнопки.** «Переиграть с хода 6» и «Пройти заново».

### 6.6. Переигровка с точки слома

`Turn.stateAfter` хранит снимок состояния после каждого хода. Переигровка = новая сессия с `parentId` и `branchTurn`, состояние копируется из хода N, история реплик до N переносится.

После завершения второй ветки — экран сравнения: две колонки, одинаковое начало, разные концовки, разница в итоговых метриках.

Это главная обучающая механика и самый эффектный момент демо: одна точка, два исхода.

## 7. Профиль паттернов

Открывается после второго пройденного уровня. Считается по логам ходов, без LLM.

| Паттерн | Правило детекции |
|---|---|
| Ломается под давлением | ≥2 раза подряд: NPC на высоком R → игрок делает `softness_no_substance` |
| Не работает с эмоцией | доля `ignore_emotion` > 30% ходов |
| Торопится к решению | `offer_options` раньше, чем `I >= 40` |
| Договаривается, но не фиксирует | финал с `R < 34`, но `C < 50` |
| Зеркалит агрессию | `mirror_aggression` хотя бы раз |
| Мягкий без опоры | `A` опускается ниже 35 на агрессивном типе |
| Не адаптируется под характер | `A < 40` на двух разных типах |

Тексты интерпретаций пишет психолог. Пример формулировки:

> **Ваш устойчивый паттерн: уступка под градусом.**
> В трёх из четырёх разговоров вы смягчали позицию через 1–2 хода после того, как собеседник повышал эмоциональный накал. Содержательных аргументов вам хватает — ломается выдержка, а не подготовка.

Это то, чего человек не знает про себя сам. Единственная причина вернуться в продукт завтра.

## 8. Геймификация

### Прогрессия

Порядок открытия: рациональный → тревожный → агрессивный. Следующий тип открывается при ≥2 звёздах на предыдущем. Сценарий 2 открывается после прохождения уровня 1 сценария 1.

Логика порядка методическая: рациональный даёт понять механику, тревожный учит замечать невысказанное, агрессивный требует держать позицию под давлением.

### Звёзды

| Звёзды | Условие |
|---|---|
| ⭐ | разговор доведён до конца без срыва |
| ⭐⭐ | + все цели руководителя достигнуты |
| ⭐⭐⭐ | + раскрыты все слои интересов и `T >= 70` |

Три звезды с первой попытки почти недостижимы. Это и есть повод переигрывать.

### Очки за ход

Начисляются сразу, видны на экране:

| Событие | Очки |
|---|---|
| конструктивное действие | +10…+25 |
| попадание в характер (`adaptiveActions`) | +15 |
| раскрытие слоя интересов | +50 |
| фиксация договорённости | +30 |
| деструктивное действие | −15 |
| зеркалирование агрессии | −25 |

Мгновенная обратная связь важнее итоговой оценки: она меняет поведение в следующем ходу, а не в следующей сессии.

### Достижения

Шесть штук, больше не нужно:

- **Дипломат** — пройти уровень, ни разу не повысив сопротивление
- **Раскопщик** — вскрыть все слои интересов
- **Хладнокровие** — пройти агрессивного, ни разу не зеркаля агрессию
- **Читатель** — угадать все три ответа на экране рефлексии
- **Работа над ошибками** — улучшить результат через переигровку
- **Полный контур** — пройти все шесть уровней

### Чего сознательно не делаем

Рейтингов между пользователями, ежедневных серий, внутренней валюты, случайных наград. Это отвлекает от сути и прямо противоречит критерию 8.4 ТЗ: дополнительные механики должны усиливать опыт, а не уводить от него.

## 9. Онбординг

Уровень 1 — сценарий «Перегрузка», рациональный тип. Самый предсказуемый персонаж, ошибки прощаются.

Формат — не отдельный туториал, а подсказки поверх первого настоящего прохождения. Человек учится, уже играя.

**Перед стартом** — оверлей из трёх экранов с подсветкой зон:

1. «Слева — ваш собеседник. Говорите голосом или текстом.»
2. «Справа — его состояние. Оно меняется от каждой вашей реплики.»
3. «У вас 14 ходов. Цель — не победить, а договориться.»

**По ходу разговора:**

| Момент | Подсказка |
|---|---|
| Ход 1 | «Начните с того, чтобы понять его. Задайте открытый вопрос или назовите то, что видите.» + 3 кнопки-заготовки реплик |
| После хода 1 | Подсветка изменившейся шкалы со стрелкой: «Смотрите — сопротивление упало. Вы попали.» |
| Ход 3 | «У него есть причины, о которых он ещё не сказал. Их нужно вытащить вопросами — следите за панелью «что вы узнали».» |
| Ход 5 | «Договорённость без конкретики не считается. Назовите, кто что делает и к какому сроку.» |
| Ход 7 | Подсказки выключаются |

Кнопки-заготовки на первом ходу критичны: человек, впервые увидевший пустое поле ввода в разговоре с ИИ, зависает. Три варианта дают точку входа, дальше он пишет сам.

Каждую подсказку можно закрыть. В правом верхнем углу — переключатель «Обучающий режим»: включён по умолчанию на уровне 1, выключен дальше, можно вернуть.

## 10. Админ-контур

Требование ТЗ, гл. 2 п. 2 и критерий 8.2. Без него теряем баллы за конфигурируемость.

**Доступ:** `/admin`, пароль из переменной окружения. Полноценная авторизация для MVP не нужна.

**Форма настройки:**

| Поле | Тип | Варианты |
|---|---|---|
| Сфера | select | IT, продажи, производство, ритейл, образование, медицина |
| Тема разговора | select + свой вариант | перегрузка, дедлайн, повышение, конфликт, падение результатов, делегирование |
| Инициатор | radio | сотрудник / руководитель |
| Роль игрока | text | руководитель проекта |
| Роль собеседника | text | Senior-разработчик |
| Цель собеседника | textarea | снизить нагрузку |
| Тип личности | select | рациональный / тревожный / агрессивный |
| Сложность | slider 1–5 | влияет на стартовые R и T, число слоёв, лимит ходов |
| Тон | select | сдержанный / эмоциональный / формальный |

**«Сгенерировать»** → LLM по жёсткому шаблону создаёт: контекст, три цели руководителя, 3–4 слоя скрытых интересов, первую реплику, примеры реплик по уровням сопротивления.

**Матрица реакций не генерируется.** Берётся базовый шаблон выбранного типа личности и корректируется коэффициентом сложности. Если отдать матрицу на генерацию, движок сломается — модель выдаст несбалансированные числа.

**Результат** показывается в редактируемой форме с человеческими подписями полей, не в виде сырого JSON. Админ правит, жмёт «Сохранить» — уровень появляется на карте с пометкой «пользовательский».

**Превью** — кнопка, открывающая первую реплику персонажа без прохождения сценария. Позволяет проверить тон за 5 секунд.

**Обязательно показать на демо:** меняем один параметр — тип личности с рационального на тревожный — пересоздаём, открываем превью. Та же ситуация, совершенно другой человек. Это прямое доказательство конфигурируемости, которое требует ТЗ.

## 13. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Латентность голоса > 6 с, демо тормозит | высокая | Текстовый режим — дефолт. Голос показываем один раз в начале демо. |
| LLM-провайдер недоступен, кончились ключи | средняя | `MOCK_MODE` с записанными ответами. Готов к дню 13. |
| Анализатор путает действия, метрики скачут | высокая | Температура 0, закрытый список, few-shot примеры. Режим отладки в админке показывает классификацию каждого хода. |
| Персонаж выходит из роли | средняя | Правило в промпте + постфильтр + fallback на заготовленные реплики. |
| Не успеваем сценарий 2 | средняя | Режем. Один сценарий × три типа достаточно. |
| Портреты выглядят дёшево | средняя | Генерация в одном стиле одним промптом, единое освещение и ракурс. Лучше три нейтральных портрета в одном стиле, чем шесть разношёрстных. |

**Порядок отрезания при нехватке времени:**

1. Достижения
2. Профиль паттернов
3. Экран сравнения веток
4. Сценарий 2
5. Голосовой ввод

**Не режем никогда:** разбор, админку, условие срыва разговора, онбординг первого уровня.

| Время | Что показываем |
