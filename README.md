# Арена переговоров — симулятор управленческих переговоров

### Команда "Муси"

Тренажёр сложных разговоров руководителя с сотрудником. Интерфейс — окно видеозвонка
с ИИ-сотрудником; справа — панель состояния собеседника и целей разговора.

**Документация:** https://dontdoitno.github.io/lct-negotiation/
В этом README.md собраны краткие сведения по решению задачи от команды "Муси". Подробная документация доступка на ссылке выше.

**Целевая аудитория:** руководители линейного и среднего звена (от тимлида до начальника отдела).

**Главное архитектурное решение:** состояние персонажа считает детерминированный
движок на бэкенде (`lib/engine/state.ts`), а не языковая модель. Модель только
отыгрывает реплику в уже посчитанном состоянии. Отсюда:

1. Исход воспроизводим — один и тот же набор действий даёт один и тот же результат.
2. Персонажа нельзя продавить только потому, что модель склонна соглашаться.
3. Метрики на экране честные — их считает код, а не нейросеть.

## Объём текущей реализации

**Сценарии живут в базе, а не в коде.** Шесть готовых загружены сидами по
`docs/psyco_specs.md`: две темы, в каждой все три типа личности. Стартовые
состояния, слои интересов и матрицы реакций перенесены из методички один в один.

| Тема | Характеры | Ходов | Слоёв интересов |
|---|---|---|---|
| Перегрузка сотрудника | рациональный, тревожный, агрессивный | 14 | 3–4 |
| Падение результатов | рациональный, тревожный, агрессивный | 14 | 4 |

Проходятся от брифинга до разбора, включая механику скрытого провала
(договорённости есть, доверия нет), обрыв разговора на угрозе увольнением и
определение типа личности участником.

**Контур администратора** (`/admin`, только для роли admin):

| Экран | Что делает |
|---|---|
| Список сценариев | Фильтры, сортировка, публикация, дублирование, удаление |
| Конструктор | Восемь секций, якорная навигация, автосохранение, проверка перед публикацией |
| Генерация | Черновик по шести полям через модель, с запасным вариантом из пресета |
| Тест-прогон | Экран звонка с панелью отладки, в статистику не идёт |
| Аналитика | Прохождения, средние метрики, распределение исходов |

Настройки администратора реально меняют поведение собеседника: тон подставляет
матрицу реакций, чувствительность умножает все дельты, слои и их цена задают
темп раскрытия. Проверяется тест-прогоном за минуту. Подробно
в [документации](https://dontdoitno.github.io/lct-negotiation/admin/overview/).

Работает также: голосовой ввод (Web Speech API, ru-RU), обучение на 6 шагов с
практикой по таксономии действий, подбор первого разговора по опросу, офлайн-режим
без ключей, 53 юнит-теста.

**Сделано, но без кнопки в интерфейсе:** форк разговора с точки слома
(`POST /api/session/:id/replay`, схема БД и API работают), фиксация договорённостей
(API + модалка написаны, в экран звонка не смонтированы), профиль паттернов игрока
(движок в `lib/engine/patterns.ts`, экрана нет).

**Не реализовано:** озвучка реплик (TTS), регистрация новых аккаунтов через
интерфейс (вход работает, сид-аккаунты ниже), сценарий «Сложная задача»,
экран сравнения веток.

## Демонстрационные аккаунты

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@razbor.local` | `admin12345` |
| Пользователь | `user@razbor.local` | `user12345` |

Создаются командой `npx tsx prisma/seed.ts` вместе с шестью сценариями.
Администратор после входа попадает в `/admin`, обычный пользователь в каталог.
Роуты `/admin/*` для не-администратора отвечают редиректом на `/cases`, API
админки — кодом 403.

Разбор по границам MVP: [docs-site/product/scope.md](docs-site/product/scope.md).

Рядом с основным движком есть экспериментальный параллельный режим оценки —
LLM-судья по рубрике гарвардского метода вместо готовых матриц реакций
психолога. Живёт в отдельных таблицах и роутах, основной движок не трогает,
см. `JUDGE_MODULE.md`.

## Архитектура

```
FRONTEND — Next.js 16 App Router + React 19 + TypeScript, Tailwind v4
  Интерфейс звонка · панель метрик · SSE-стриминг реплик · разбор
  Дизайн-система @astryxdesign/core

BACKEND — Next.js Route Handlers (Node runtime)
  Ход разговора:
    1. Analyzer  → классификация реплики в закрытый список из 22 действий
    2. State Engine → чистый TS, БЕЗ обращения к LLM — единственное место,
                       где решается исход
    3. Actor     → реплика персонажа (стриминг)
  Scenario/Persona Loader · Debrief Builder

  PostgreSQL (Prisma): сценарии, аккаунты, сессии, ходы
  LLM-провайдеры изолированы в lib/llm/provider.ts:
  Yandex Cloud (native и OpenAI-совместимый /v1/responses), OpenRouter, mock
```

В `lib/engine/` нет ни одного импорта из `lib/llm/` и ни одного обращения к БД —
движок нельзя случайно сделать зависимым от модели.

Дизайн психологической модели (матрицы реакций, скрытые интересы, три асимметрии
между типами личности) находится в `content/personas/*.json` — правится
психологом напрямую, без деплоя кода. Ключевые асимметрии проверены юнит-тестами
в `tests/engine.test.ts`.

## Инструкция запуска

```bash
npm install
cp .env.example .env          # вписать DATABASE_URL и DATABASE_URL_UNPOOLED
npx prisma migrate deploy
npx prisma generate
npx tsx prisma/seed.ts        # шесть сценариев и два аккаунта
npm run dev
```

Открыть http://localhost:3000. Нужен Node.js 20.9+ (проверено на 24.12) и пустая
база PostgreSQL. Ключи к языковым моделям для первого запуска не нужны: в
`.env.example` включён офлайн-режим.

Где взять базу (любой из трёх вариантов) — в документации, раздел
[Быстрый старт](docs-site/run/quickstart.md). Самый короткий путь, если проект
уже связан с Vercel: `vercel env pull .env.local --yes`.

Для демонстрации лучше рабочая сборка: `npm run build && npm start`.

**Публичный деплой:** пошагово в [docs-site/run/deploy.md](docs-site/run/deploy.md).
В репозитории уже настроены схема под PostgreSQL, трассировка файлов контента,
генерация клиента Prisma при сборке и регион Франкфурт.

> **Если при старте падает `Cannot find module '../lightningcss.darwin-*.node'`**
>
> Это несовпадение архитектуры нативных бинарников, а не ошибка в коде. У npm
> есть [известный баг с опциональными зависимостями](https://github.com/npm/cli/issues/4828):
> при установке он оставляет бинарники только под ту архитектуру, в которой
> запущен сам, и выкидывает остальные. Если `npm install` прогнали из-под Rosetta
> (x64), а `npm run dev` запускается нативно (arm64) — или наоборот — ломается
> сборка CSS.
>
> Затронуты `lightningcss`, `@tailwindcss/oxide`, `@next/swc`, `@rolldown/binding`.
> Проверить, что стоит: `ls node_modules | grep darwin`.
>
> Самое надёжное — держать в `node_modules` обе архитектуры сразу, тогда
> работает и нативный запуск, и Rosetta. Простое лечение: `rm -rf node_modules
> package-lock.json && npm install` из обычного терминала (не из-под Rosetta).

## Офлайн-режим и ключи

По умолчанию в `.env.example` стоит `MOCK_MODE="true"` — режим полностью офлайн:
анализатор реплик работает на детерминированной эвристике по ключевым словам
(`lib/llm/analyzer.ts`), актёр отвечает заготовленными репликами персонажа
(`lib/llm/actor.ts`). Метрики, слои интересов, условия финала и разбор считаются
точно так же, как с моделью. Внешние ключи не нужны.

Чтобы реплики генерировала модель — Yandex Cloud Foundation Models:

```
MOCK_MODE=false
LLM_PROVIDER=yandex
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
YANDEX_API_MODE=native          # responses — для DeepSeek/Qwen/GPT-OSS
YANDEX_MODEL=yandexgpt-lite
```

Альтернатива — OpenRouter (`LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY`).
Пошагово, где взять ключ и каталог: [docs-site/tech/services.md](docs-site/tech/services.md).
Полный список переменных: [docs-site/run/environment.md](docs-site/run/environment.md).

Если провайдер недоступен, актёр делает две попытки и берёт заготовленную реплику —
ход завершается, метрики считаются, разговор продолжается.

## Использованные сервисы

- **LLM:** Yandex Cloud Foundation Models или OpenRouter, оба опциональны
  (при `MOCK_MODE=false`) — реплики персонажа и, по флагу `ANALYZER_LLM`,
  классификация реплик руководителя.
- **Распознавание речи:** Web Speech API в браузере, без внешнего сервиса и ключей.
- **БД:** PostgreSQL через Prisma. Единственный обязательный внешний сервис.
  На Vercel подключается из Marketplace, переменные приходят сами.

## Методологическая база

Гарвардский метод принципиальных переговоров, модель работы с сопротивлением,
типология стратегий поведения в конфликте (соперничество / избегание /
компромисс). Модель оценки (метрики R/T/I/S/C/A), матрицы реакций и сценарии
разработаны психологом команды на основе `docs/psyco_specs.md` — не сгенерированы
языковой моделью.
