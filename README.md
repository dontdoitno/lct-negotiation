# Разбор полётов — симулятор управленческих переговоров

Тренажёр сложных разговоров руководителя с сотрудником. Интерфейс — окно видеозвонка
с ИИ-сотрудником; справа — панель состояния собеседника и целей разговора.

**Целевая аудитория:** руководители линейного и среднего звена (от тимлида до начальника отдела).

**Главное архитектурное решение:** состояние персонажа считает детерминированный
движок на бэкенде (`lib/engine/state.ts`), а не языковая модель. Модель только
отыгрывает реплику в уже посчитанном состоянии. Отсюда:

1. Исход воспроизводим — один и тот же набор действий даёт один и тот же результат.
2. Персонажа нельзя продавить только потому, что модель склонна соглашаться.
3. Метрики на экране честные — их считает код, а не нейросеть.

Полная спецификация продукта и психологическая методология — в `docs/negotiation-simulator-spec.md`
и `docs/psyco_specs.md`.

## Объём текущей реализации

Сценарий 1 «Перегрузка сотрудника» реализован полностью — 3 уровня (рациональный,
тревожный, агрессивный тип), играбельные от брифинга до разбора с механикой
скрытого провала и переигровки с точки слома.

Скоуп-ауты этой итерации (см. `docs/negotiation-simulator-spec.md` для полной версии):
голосовой ввод (STT/TTS), сценарий 2 «Сложная задача», админ-контур генерации
уровней, экран сравнения веток, достижения и профиль паттернов игрока (движок для
паттернов есть в `lib/engine/patterns.ts`, но экран профиля не собран).

## Архитектура

```
FRONTEND — Next.js App Router + TypeScript, Tailwind v4
  Zoom-интерфейс · панель метрик · SSE-стриминг реплик · разбор

BACKEND — Next.js Route Handlers (Node runtime)
  Turn Orchestrator:
    1. Analyzer  → строгая классификация реплики в закрытый список действий
    2. State Engine → чистый TS, БЕЗ обращения к LLM — единственное место,
                       где решается исход
    3. Actor     → реплика персонажа (стриминг)
  Scenario/Persona Loader · Debrief Builder

  SQLite (Prisma) · LLM-провайдер (OpenRouter, изолирован в lib/llm/provider.ts)
```

Дизайн психологической модели (матрицы реакций, скрытые интересы, три асимметрии
между типами личности) находится в `content/personas/*.json` — правится
психологом напрямую, без деплоя кода. Ключевые асимметрии проверены юнит-тестами
в `tests/engine.test.ts`.

## Инструкция запуска

```bash
npm install
cp .env.example .env
npx prisma migrate dev
npm run dev
```

Открыть http://localhost:3000.

По умолчанию `MOCK_MODE=true` — режим полностью офлайн: анализатор реплик работает
на детерминированной эвристике по ключевым словам (`lib/llm/analyzer.ts`), актёр
отвечает заготовленными репликами персонажа (`lib/llm/actor.ts`). Внешние ключи не
нужны — это и есть требуемый по ТЗ офлайн-режим для демо.

Чтобы включить реальные вызовы LLM (OpenRouter), заполнить в `.env`:

```
MOCK_MODE=false
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=openai/gpt-4o-mini
```

## Тесты

```bash
npm run test   # vitest — детерминированность движка, три ключевые асимметрии,
               # раскрытие скрытых интересов, условия завершения
npm run lint
```

## Использованные сервисы

- **LLM:** OpenRouter (опционально, при `MOCK_MODE=false`) — классификация реплик
  и генерация реплик персонажа.
- **БД:** SQLite локально (`prisma/dev.db`), миграция на Postgres — смена одной
  строки в `prisma/schema.prisma` (`provider = "postgresql"`) плюс `DATABASE_URL`.

## Методологическая база

Гарвардский метод принципиальных переговоров, модель работы с сопротивлением,
типология стратегий поведения в конфликте (соперничество / избегание /
компромисс). Модель оценки (метрики R/T/I/S/C/A), матрицы реакций и сценарии
разработаны психологом команды на основе `docs/psyco_specs.md` — не сгенерированы
языковой моделью.
